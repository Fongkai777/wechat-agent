# WeChat Agent

[English](README.md) | [中文说明](README.zh-CN.md)

把你自己的 macOS WeChat 聊天记录整理为可检索的个人知识库：浏览聊天、跨会话问答，并通过定时只读任务追踪相关信息，保留可回查的消息依据。

应用在本机运行，但**本地保存不等于 AI 离线运行**：启用云端模型后，相关聊天文本、Embedding 输入或语音音频会发送给配置的服务商，并可能产生 API 费用。

它目前支持：

- 解密并读取你自己导出的 WeChat `db_storage` 数据库。
- 用接近微信的方式浏览原始聊天内容。
- 展示文本、链接、转发聊天记录、图片、视频、表情包和语音占位信息。
- 对本地语音做 OpenAI 语音转文字，并把转写结果缓存起来。
- 建立全文索引和语义索引，用于聊天记录问答。
- 在 RAG 检索页查看 Query Planner、召回分路、融合排序、入模片段和索引状态。
- 在网页里配置问答、Embedding、Rerank 和语音转写模型。
- 在「任务助手」里保存多个定时任务，由模型调用只读聊天工具检查并保存结果。

## 两条检索路径

**聊天问答**使用项目内实现的 Python / SQLite 检索链路：

```text
问题与对话历史
  → 查询规划与改写
  → 向量召回 + SQLite 词法召回 + 联系人软匹配
  → RRF 融合 + 可选的 LLM 重排
  → 选取上下文 → 带消息依据的回答
```

联系人匹配只作为召回和排序信号，不会把搜索硬限制在名字命中的联系人中。目前 Rerank 是调用聊天模型判断候选相关性，并非使用 OpenAI 的专用 rerank 接口。

**任务助手**使用另一条链路：

```text
任务描述与滚动时间窗
  → 问答模型选择只读工具
  → search_messages / list_private_chats / read_chat
  → 已同步的解密快照与已保存的语音转写
  → 结构化结果 → 引用校验 → 保存执行历史
```

任务目前不依赖问答的向量索引或联系人索引。完整返回关键词匹配不等于语义上穷尽所有相关信息；检索词、本地数据是否齐全以及模型上下文容量仍会影响结果。大范围任务可能更慢、费用更高。

## 定时任务

「任务助手」支持新增、编辑、暂停和删除任务，周期为「每 + 数字 + 小时／天」（1–365），例如半天为每 12 小时、每周为每 7 天；一天按 24 小时计算。
卡片上的「立即执行」会在后台运行一次并保存执行记录，关闭页面不会终止。启用中的任务从本次开始时间重新计算下次执行；暂停的任务可手动执行一次，不会恢复定时。手动和定时共用执行锁，已有任务执行时不会再启动另一个。「停止执行」只停止本次后续请求，不改变定时开关。
检索范围为「最近 + 数字 + 天／周／月」，默认最近 1 天。支持 1–90 天、1–12 周或 1–3 个月；一天为 24 小时，一周为 7 天，月份按日历回推（不存在对应日期时取月末）。范围随每次执行滚动，不会被上次检查时间缩短；模型工具只能在范围内进一步筛选。
首次执行在保存后的一个周期；修改任务内容、周期、检索范围或重新启用会重新计时。关闭浏览器不影响执行，但本地服务必须运行，电脑不能处于休眠状态。
错过多个周期后只补做一次，不会连续补跑。任务正在执行时可以暂停，当前 API 请求返回后停止后续请求；执行结束前不能编辑、删除或重新启用。

任务直接交给当前问答模型，由模型选择搜索聊天、检查私聊和读取会话上下文等工具，不按实习、回复、美食分别定义固定工作流。
工具读取已同步的解密快照，支持已保存的语音转写，不需要先重建语义索引。本版工具是关键词检索，不是现有问答页的向量混合检索。
以用户设定的时间窗为范围，不再截取前 30 条匹配、最近 1000 条会话消息或最近 40 条上下文；返回全部关键词匹配，私聊工具读取范围内全部私聊及消息。任务消息不再裁成 1200 字，转发记录也不再只取前 80 项。结果记录 matched／returned／scanned 数量，全部来源可在执行历史查看。关键词匹配完整不等于语义上穷尽所有相关信息；工具只读，建议回复不会自动发送。

新执行使用 Structured Outputs（JSON Schema）返回结论、事项、建议和必要提醒；问答模型须同时支持工具调用和结构化输出。服务端校验字段、长度和来源编号，格式错误、拒答或截断会记录为失败，不会当成无发现。旧版纯文本历史保持原样。
最终事项和每项来源编号不设数量上限。引用在单次执行内跨工具统一登记；编号不存在时将有效编号反馈给模型，最多纠正两次，不重跑整次检索、不猜测替换编号。纠正后仍无效则记录失败，执行历史保留错误编号以便排查。
桌面上每个任务独占一行，左右卡片等高，长结果在右侧内部滚动。事项引用可点开原始消息；「历史记录」可查看最近 20 次执行的完整结果、检索来源、工具调用概况和模型返回的 Token 用量。
任务和记录保存在已被 Git 忽略的 `web_cache/goals.sqlite3`；当前运行复用问答模型及其 API Key，定时或手动执行会产生模型费用，查看结果和历史不会触发模型调用。

## 后台执行

聊天问答、单条／批量语音转写、全文／语义索引和检索调试由服务端后台执行。切换应用窗口、页面标签、刷新或关闭浏览器不会取消执行；重新打开后恢复进度。只有明确点击「停止」才请求取消，正在进行的 API 请求可能仍需等待返回，也可能已产生费用，但之后不会继续发起模型请求。

「一键准备检索」的转写、全文索引、语义索引三个步骤也在服务端依次执行；前一步失败或明确停止时，不会继续下一步。网络恢复只重新查询进度，提交回执丢失时只查询原执行编号，不重新提交付费请求。

问答的完成、失败和停止状态都会写入本地历史；转写和索引仍使用原有持久化缓存。进度日志只在当前服务进程内保留最近 160 条，完成执行保留约 32 个。服务重启、关机或休眠不等于切换窗口：重启会中断未完成工作，问答标记为中断，不会自动重复调用付费模型。

任务历史的「模型调用」记录每轮结束原因、输出和推理 Token 用量，不记录模型内部推理文本。移除了固定 8 次工具调用、4 分钟执行时间和人为 6,000 输出 token 上限。模型服务自身的上下文／输出容量及请求超时仍可能使任务失败，应用不会为通过请求而静默丢弃匹配结果；数据越多，模型耗时和费用可能越高，可以随时停止执行。正文为空、工具全部失败和格式错误分别报告，不自动重跑整次执行。
上次报告仅用于避免重复汇报，不能替代重新核查证据。定时服务重启后会将未完成的记录标为中断。
任务模型的单次网络响应读取等待上限为 300 秒，独立于任务检索的时间范围。超时不自动重发请求；记录失败轮次、已检索来源数量和输入字符数，该轮未收到的 Token 用量标为未知，不能当作零费用。停止操作仍会在正在等待的网络请求返回或超时后生效。

> 注意：这个项目只适合处理你自己有权访问的聊天数据。`all_keys.json`、解密数据库、网页缓存、转写结果和原始媒体文件都不应该提交到 Git。

## 数据目录

项目默认期望根目录下有一份复制出来的微信数据库目录：

```text
db_storage/
  message/message_0.db
  contact/contact.db
  session/session.db
  ...
```

这些数据库是 SQLCipher 加密的。你还需要从自己已登录、正在运行的 WeChat 客户端里提取数据库密钥，保存为 `all_keys.json`，之后才能解密和浏览聊天记录。

## 快速开始

需要 Python 3.9+、你自己的 macOS WeChat 4.x 数据库及匹配的数据库密钥。密钥提取受微信/macOS 版本和权限影响，本项目不是适用于所有版本的一键备份解码器。

在仓库根目录创建启动脚本使用的虚拟环境并安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

检查数据库：

```bash
python3 -m wechat_agent inspect
```

拿到 `all_keys.json` 后解密数据库：

```bash
python3 -m wechat_agent decrypt --keys all_keys.json
```

解密过程会把加密的 SQLite `*.db-wal` 合并到解密副本里，这对最近下载但还没 checkpoint 到主 `.db` 文件里的语音和媒体记录很重要。

启动本地网页：

```bash
bash scripts/start_web.sh
```

然后打开：

```text
http://127.0.0.1:8787
```

默认只展示 2023 年以来的记录。这个时间过滤只影响网页展示和索引，不会删除或改写原始微信数据库。

重启原来 8787 端口的服务：

```bash
bash scripts/restart_web.command
```

启动脚本支持 `WECHAT_AGENT_HOST`、`WECHAT_AGENT_PORT`、`WECHAT_AGENT_SINCE` 覆盖默认设置；重启脚本固定操作 8787 端口。未单独做好访问保护时，请保持默认的 `127.0.0.1` 本机地址。

如果想读取原始微信容器目录，也可以用环境变量指定，不需要把路径写进代码：

```bash
WECHAT_AGENT_DB_STORAGE="/path/to/db_storage" bash scripts/start_web.sh
```

也可以把路径保存在 `web_cache/source.json`，之后重启会沿用这个数据源：

```json
{"db_storage": "/path/to/db_storage"}
```

这个本机配置不会提交到 Git。命令行参数和环境变量优先于配置文件。
启动时会同步一次，运行中每 60 秒自动检查更新；聊天列表上方的“同步最新消息”按钮可立即手动同步，包括尚未写回主数据库的 WAL 消息。
问答、语音转写或索引任务运行时会延后自动同步，避免替换正在读取的数据。网页会自动更新聊天列表；翻阅旧消息时不会强制滚动到底部。
只有发生变化的数据库才会重新解密；同步不会自动调用模型或重建语义索引。
如果数据源只是复制出来的文件夹，它本身不会随微信收到新消息而更新；要持续同步，需使用可访问的实时数据库目录，或自行更新源副本。
同步后的检索索引可在 RAG 页更新。源目录不可用时，状态栏会提示正在使用旧副本。

也可以直接指定参数：

```bash
python3 -m wechat_agent.web --db-storage db_storage --since 2023-01-01 --port 8787
```

如果直接读取微信容器目录时被 macOS 权限拦住，请从 Terminal.app 启动，并给 Terminal 开启 Full Disk Access。

## 网页功能

网页目前分成五个主要 tab：

- 聊天内容：浏览联系人、群聊和消息流。
- 聊天问答：像聊天界面一样对所有聊天记录提问，支持多轮对话和历史会话管理。
- 任务助手：设置任务、执行周期和检索范围，查看结果、引用和执行历史。
- RAG 配置：维护索引、查看日志并调试检索链路，包括查询改写、全文召回、语义召回、RRF 融合、Rerank 和入模片段。
- 大模型配置：配置语音转文字、问答模型、Embedding 模型和 Rerank 模型。

RAG 检索不会把“联系人命中”当作硬过滤。主检索会走全库，联系人只作为软召回和排序信号，避免因为关键词撞上联系人备注而漏掉真正相关的聊天内容。

检索调试中的「调试片段数」只用于本次调试请求，不会保存为问答配置。聊天问答的片段数量由「大模型配置 → 聊天问答 → 检索条数」单独控制。进入 RAG 配置页时会刷新索引与语音状态，执行索引任务期间继续自动更新。

聊天浏览采用游标分页：首次加载最近 100 条，上翻到顶部或点击「更早消息」再加载 100 条。后端先在每个消息分片中执行带 `LIMIT` 的查询，合并选出一页后，才解压消息和解析该页的媒体；不再缓存或格式化整个会话。游标由消息时间、分片、表名和行号组成，避免同步追加消息导致偏移分页重复或漏条。此处的分页不限制 RAG 或任务的历史检索范围，也不会删除历史记录。

聊天侧栏可以拖动调整宽度，长消息预览以省略号展示，不会截断保存的消息内容。

有新消息时，在底部阅读会追加显示；正在翻历史时保留滚动位置，显示「查看最新消息」按钮。显示窗口以 1,000 条为上限，淘汰远离阅读位置的节点后，仍能通过游标向前或向后重新加载；若裁剪会移除当前阅读位置，则延后裁剪。无数据变化的同步检查不再刷新聊天列表。修改后的旧消息和语音转写会在可见页刷新或重新打开会话时读取最新快照。单页 API 使用 `before` / `after` 游标，不再接受旧的 `offset` 参数；升级后需重启原来的服务并刷新网页。

RAG 页的「一键准备检索」按顺序执行：语音转文字 → 全文索引增量更新 → 语义索引增量更新。语音默认跳过已有转写，模型参数仍在「大模型配置」页管理。可以停止流程；已经保存的转写和索引结果不会清空。导致流程无法继续的错误会中止后续步骤，少量单条语音失败则会在完成状态中单独提示。

同一页支持「定时更新」：设置每 N 小时或天并保存，默认关闭。首次从保存时开始计时，之后从每次定时执行结束计算下一周期；手动一键更新不改变定时计划。到期时若有其他转写或索引操作，会等待其结束。关闭定时不会中止正在执行的流程，停止本次流程请使用「停止」。

状态栏以最近一次完整更新的结果为准，包含手动和定时执行：新执行成功后不再显示旧失败提示，结果在服务端保存，刷新页面仍然有效；手动结果不会修改原来的下次定时时间。仅刷新状态或单独执行检索不算更新成功，不会清除失败提示。

定时配置与最近执行状态保存在 `web_cache/rag_schedule.sqlite3`。关闭网页不影响后台计时，但 8787 服务必须运行，电脑也需保持唤醒；恢复服务后只补执行一次到期更新，不逐次补跑遗漏周期。未完成的旧执行标为中断并等待下一周期。自动更新复用现有模型配置，仅补转写和增量索引，相关 API 调用仍按用量计费。

Embedding 的 DNS 域名解析错误发生在请求发送前，当前批次会等待约 2 秒、4 秒各重试一次，并显示进度；点击停止可取消等待。持续失败时会保留已写入的向量，下一轮只补齐缺失部分。响应超时、证书错误、鉴权和配额错误不会触发此重试，避免在发送状态不明时重复请求。DNS 错误不等同于 Key 无效，应先检查网络、DNS 或代理连接。

`voice_transcriptions.json` 新增、修正或删除转写时，更新索引会核对已有语音消息，只更新变化的文本和全文检索项，并将受影响的语义块及其邻接消息重新排入待更新队列。无关消息和向量保留，不再仅因语音缓存变化而全量重建。账号、时间范围或不兼容的索引结构变化仍可能要求全量重建。

## 媒体说明

聊天浏览器会从 `db_storage` 同级的 `msg/` 目录读取媒体文件。

- 视频：本地存在匹配的 `.mp4` 或缩略图时会展示。
- 图片：本地 `.dat` 文件本身已经是浏览器可读的 JPEG、PNG 或 WebP 时会展示。
- 微信内置小表情：例如 `[Sob]`、`[Whimper]` 会保留为文字，便于后续情绪分析。
- 表情包：会解析 `type=47` 的 XML，优先找本地缓存，找不到时尝试使用消息里的 CDN 预览地址。
- V2 加密图片：需要额外的 `image_aes_key`，可用 `WECHAT_AGENT_IMAGE_AES_KEY` 和 `WECHAT_AGENT_IMAGE_XOR_KEY` 传入，或写入本地 `config.json`。
- 语音：需要本地音频 blob、SILK 解码能力和语音模型配置。云端转写可用 `python -m pip install 'pilk>=0.2'` 安装解码依赖；本地 Whisper 是可选方案，`scripts/install_voice_deps.sh` 会同时安装 `pilk` 与 `openai-whisper`。网页可以批量转写语音，并跳过已转写的内容。

只有 XML 元数据时无法凭空恢复音频；缺失或过期的图片、视频、转发记录附件也不能保证展示。外部 CDN 可能拒绝访问。链接分享、转发记录、通话和已支持的系统消息会解析展示，具体兼容情况取决于消息格式和微信版本。

## RAG 索引

构建命令行聊天索引：

```bash
python3 -m wechat_agent index
```

这条命令生成聊天清单，不等同于网页的全文／语义索引。使用模型功能前，请先在「大模型配置」设置相应配置和凭据，再到「RAG 配置」准备检索。

网页里的 RAG tab 维护两类索引：

- 全文候选库：SQLite + FTS，用于关键词召回和精确补漏。
- 语义索引：把聊天记录切成语义片段，调用 Embedding API 生成向量，用于语义召回。

索引支持增量更新：如果只是消息库追加新记录，系统会扫描新增消息并补写索引；如果账号、时间范围或关键文件结构发生变化，才需要全量重建。

## 导出聊天

按用户名或群聊 id 导出单个聊天：

```bash
python3 -m wechat_agent export --chat 1234567890@chatroom --name "My Group"
```

输出会写到 `exports/`，解密副本会写到 `decrypted/`。这两个目录默认被 `.gitignore` 忽略。

## 隐私与安全

仅处理你有权访问的数据。数据库密钥、解密数据、模型凭据、语音转写和媒体均为敏感信息；标准本地数据路径已加入 `.gitignore`，发布前仍应检查暂存文件。

问答、任务、Embedding、重排和云端转写会把相关数据发送给配置的服务商；CDN 媒体预览也会发起外部请求。使用他人的消息前，请了解服务商的数据保留规则并取得必要授权。本项目不是腾讯／微信的官方产品，也未获得其背书。

## 密钥提取

详见 [docs/KEY_EXTRACTION.md](docs/KEY_EXTRACTION.md)。

简短说：macOS WeChat 4.x 的数据库密钥不在 `db_storage` 文件夹里，而是在已登录的 WeChat 客户端进程内。你需要从自己的运行中客户端提取密钥，生成 `all_keys.json`，本项目才能用它解密本地数据库。

`all_keys.json` 可以解密你的微信聊天数据，请务必只保存在本机，不要提交到 GitHub、云盘或公开聊天里。
