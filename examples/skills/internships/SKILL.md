# 实习信息追踪

在用户设定的时间窗内查找与任务相关的实习信息，不限定城市、行业或联系人，也不要求每项都是岗位。宣讲、内推、申请通知和信息更正均可入选。

## 执行流程
1. 用完整任务描述做语义检索，用包内关键词做 SQL 补召回；消息按真实身份去重。
2. 给候选补齐邻近上下文，按完整窗口分批，不用固定候选条数截断。
3. 通过原生 Tool Calling 调用共享平台工具。模型可以改写查询、查看会话、查找人物、补查上下文；不要求先抽取槽位或设置全局路由。
4. 首轮两路召回均为空时，仍把任务及时间窗交给模型，要求通过 `search` 改写查询补查，再生成结果。补查失败不保存为“未发现”。
5. 模型输出结构化 JSON，`is_relevant` 表示与任务相关，不是“是否为实习岗位”。非岗位信息无需填写公司、联系方式等不适用字段。
6. 核验所有引用。只有各事实字段都相同的结果才合并引用；日期、联系方式不同的同名信息分别保留并提示核对，不默认旧消息或新消息一定正确。明确更正由模型结合原始证据处理，不确定差异不能被丢弃。

## 接口和引用
- `api.cite` 的 `reference` 用于输出引用；不是共享工具的 `evidence_id`。
- `surrounding` 共享工具的 `source_ids` 必须来自共享工具返回的 `evidence_id`。
- 任务时间范围始终生效；可选过滤只作用于当次工具调用。
- 全部代码、提示词、查询和测试均在包内；平台不内置实习业务规则。

## 文件与限制
- `workflow.py`：召回、上下文、工具循环、预算和输出逻辑。
- `test_skill.py`：虚构数据覆盖空结果补查、补查命中、非岗位信息、冲突日期和联系方式、非法引用、同消息多岗位、超预算等。
- `manifest.json`：最多 16 次模型调用（包括 search 重排）、8 次 Embedding，900 秒。资源不足会失败，不静默保存部分成功。
- `PLATFORM_API.md`（保存至任务时附带）：当前公共接口契约。

相关性检索不是全量主题审计，可能漏检；模型自主补查的分页也不代表遍历全部消息。输出会保留覆盖说明。内置测试不调用真实模型，不能代替真实回答质量评测。
