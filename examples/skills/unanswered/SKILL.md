# 忘回私聊检查

在任务时间窗内，读取每个私聊最后一条物理消息，列出对方最后发言或身份、顺序不确定的会话。

## 执行流程
1. `api.chats()` 获取会话，在包内筛选私聊。
2. 每批最多 100 个会话，调用 `api.messages_batch(chat_ids, latest=1)`。平台沿用原始消息读取器，保留未渲染消息、表情、通话和顺序不确定标记，不依赖全文索引。
3. 对比 `sender_username` 和当前账户 ID；自己最后发言且顺序确定时跳过。未知身份或同秒跨分片顺序不确定时列出并提示确认。
4. `api.cite()` 校验原始来源，返回全部候选。任何读取失败或批次缺少会话都中止，不把失败当成“无待回”。

## 文件与预算
- `workflow.py`：全部查询、判断和展示逻辑，可自行编辑。
- `test_skill.py`：虚构数据测试，包括 1200 个私聊、未知身份、顺序歧义、读取失败和引用错误。
- `manifest.json`：仅 `messages.read` 权限；200 次接口调用、300 秒；不调用模型或 Embedding。
- `PLATFORM_API.md`（保存至任务时附带）：当前平台接口说明。

批量读取降低跨进程调用次数，宿主仍需读取各会话的原始消息。超时或安全预算不足会明确失败，不静默截断。该规则只找“可能待回”，不会判断每条消息是否必须回复，也不会发送消息。
